# Phase 7B frontend audit

2026-10-17. Read the Phase 7A audit, implementation/closeout reports and server test documentation. Backend reservation, idempotency, cleanup, authentication and media contracts are retained.

Baseline before edits: client lint passed without diagnostics; server tests 17 passed, 0 failed/skipped; Vite production build passed, 2,008 modules, 2.82 seconds, main JS 337.33 kB / 109.51 kB gzip.

Current public pages repeat styles and use oversized rounded/gradient blocks. Home duplicates service descriptions, lacks category navigation and a clear process; the only bundled hero asset is unrelated starter artwork. Real catalogue media will be used where present. Header is crowded at intermediate widths. Footer/contact use settings, but contact shows empty coming-soon sections. About is only an introduction. Shop loads the real catalogue but filters are local-only, with no sorting/pagination/mobile filter panel. Product cards shrink real media unnecessarily; details lack related items and relevant assistance. Cart trusts parsed localStorage shape and stale stock, and quantity controls lack accessible names. Checkout has durable idempotency but needs stock refresh, explicit ambiguous-retry handling and better validation. Booking links send a service query that the form ignores. Native form fields and status states are inconsistent. MainLayout and some pages nest main landmarks. No route metadata exists. Admin route splitting, focus traps, dynamic business settings and existing real APIs remain valuable foundations.

Plan: shared storefront tokens/primitives; clear sales/service hierarchy; URL-backed catalogue filters using the existing full catalogue endpoint; real ordered galleries; validated persistent cart and refreshed stock; preserve the order service and key across ambiguous retries; professional booking/contact content; accessible responsive verification at seven widths. No backend behavior changes, credential changes, invented business facts or deployment.
